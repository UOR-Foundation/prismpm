# Agent Guidelines for PrismPM

- SPEC.md is normative; README prose is explanatory.
- No handwritten PrismPM `.lean` source or `lakefile.lean` may be committed. All PrismPM Lean code is generated from `.lex.tex` by LexLean. The only upstream-source exception is the exact 4-file compiler-authority closure in SPEC §9 and `LEXLEAN_AUTHORITY_SOURCES` (`language/preservation-1.2/modules/LexLeanTarget/{RustSemantics,RustSyntax,TargetSemantics,TargetSyntax}.lean`), admitted only from the pinned LexLean revision `e0b74b81e6f49c83596a957d232c8383a5db1a25` (the commit of the annotated `v0.4.0` tag and of the LexLean v0.4.0 release) through the registered package, complete dependency/tree checksums, matching clean package VCS provenance, and exact archive-member/tree byte equality. The extraction adapter and preservation library are `.lex.tex` notation in that package. This does not admit other vendored Lean or any PrismPM model, proof, or replacement application behavior. The second and last exception is the WASM Lean prover's driver, the 2 files in `LEAN_PROVER_DRIVER_SOURCES` (`sdk/npm/lean-prover/driver/{Elab,SymList}.lean`), admitted only as the exact bytes a LexLean release publishes, pinned with its revision and each file's BLAKE3 label in `model/dependencies.toml` (`lean-prover-driver`); the prover's generated patch to Lean's C++ is pinned the same way and may change nothing under Lean's `src/kernel/` but the one declaration `xtask audit` names. Neither admits PrismPM-authored Lean.
- Do not introduce placeholder URLs, wildcards in internal dependencies, unpinned toolchains, or unstaged modifications.
- Every public capability and diagnostic is registered in `model/*.toml` and covered by conformance fixtures.
